# Codex на Ubuntu VM — выпустить обновлённый интерфейс в Telegram Serverless

Запускать после merge PR с унификацией игрового интерфейса. Рабочий каталог: `/home/dvpot/projects/github/umnozhayka`. Source of truth — GitHub `dvpot/umnozhayka`, ветка `main`. Ожидаемое приложение: `@umnozhayka_tgbot`, app ID `8854507045`.

Прочитай `AGENTS.md`, `README.md`, `docs/PLAN.md`, `docs/TELEGRAM_DEPLOY.md`, `docs/CODEX_CHECK_QA_TASK.md` и этот файл. Начни с `git status -sb`, `git fetch origin`; сохрани локальные изменения и обновляй `main` только fast-forward. Запиши актуальный SHA после merge PR. Секреты не запрашивай, не читай и не выводи. Не используй `--force`.

1. Выполни `npm ci && npm run check`, `node --check app/app.js`, `git diff --check`. Проверь браузерную приёмку именно на актуальном `main`: 280, 320, 390 и 768 px; отсутствие горизонтальной прокрутки; стартовый экран загрузки и плавное открытие сохранённого состояния; селекторы в шапке; одинаковую высоту карточки; свайп на карточке, отсутствие свайпа в шапке; цвет и блокировку вариантов; ввод неверного ответа, его исправление и переход с неверным ответом; счёт, сброс, итог, настройки озвучивания.
2. По порядку выполни `npx tgcloud fetch`, `npx tgcloud status`, `npx tgcloud diff`. Сверь app ID `8854507045` с настройками именно `@umnozhayka_tgbot`, текущую revision, модули и перечень изменений. Ожидаются статические файлы Mini App из `dist/`. При неожиданных изменениях ничего не перезаписывай: повтори fetch/status/diff и разберись с причиной.
3. Только после зелёных проверок, соответствующего app ID и ожидаемого diff выполни `npm run deploy` без дополнительных флагов. Если CLI вернёт ошибку, сначала установи, загрузились ли файлы, и не повторяй публикацию вслепую.
4. После публикации выполни `npx tgcloud fetch`, `npx tgcloud status`, `npx tgcloud diff`. Подтверди новую фактическую revision, целевые файлы, отсутствие нежелательных модульных изменений и чистый diff. Проверь HTTP 200 URL приложения, `app.js`, `engine.js`, `styles.css`, затем открой публичное приложение в чистом браузерном контексте и проверь новые элементы шапки и расположение карточки. Проверку в браузере не называй проверкой Telegram WebView.
5. Запиши фактический результат (SHA, команды и тесты, ширины браузера, app ID, старую/новую revision, итоговый diff, HTTP и реальную поверхность QA) в `docs/TELEGRAM_DEPLOY.md`. Сделай отдельную ветку и PR с CI; после merge синхронизируй VM с GitHub `main`. Не записывай секреты и не заявляй результаты, которые не проверял.
