# Codex: независимая проверка и запуск

Перед началом прочитать AGENTS.md, README.md, docs/PLAN.md, docs/TELEGRAM_DEPLOY.md и актуальный main репозитория dvpot/umnozhayka.

1. Независимо выполнить npm run check, браузерный smoke-test на мобильном viewport, проверить 10-секундный таймер, свайпы, корректное восстановление localStorage и отсутствие повторов.
2. Проверить действительную конфигурацию Telegram Serverless для @umnozhayka_tgbot. Если CLI авторизован, получить подтверждение, что CLI Access token взят из Serverless-настроек именно этого бота в BotFather; сверить публичный app ID из `status` с префиксом токена (CLI не показывает username) и убедиться, что не задан чужой `TGCLOUD_TOKEN`. Затем выполнить `npx tgcloud fetch` и проверить `status`/`diff`; без свежего fetch они сравнивают только локальную копию со снимком. `status` может дополнительно показать состояние webhook. Публиковать лишь после подтверждения цели и отсутствия неожиданных удалений. После публикации проверить URL, `/start` и Mini App в Telegram. Если CLI Access token отсутствует, не запрашивать его в чате: указать владельцу точный путь в BotFather и дождаться локального `npx tgcloud login`.
3. При ошибках разработать исправления и открыть PR. Не дублировать существующую работу Primary.
4. Не запрашивать и не публиковать токены/данные детей в чат, Issues, PR и логах.
