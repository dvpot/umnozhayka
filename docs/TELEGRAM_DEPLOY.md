# Telegram Serverless — @umnozhayka_tgbot

Официальная документация: https://core.telegram.org/bots/serverless

Текущий официальный процесс и возможности CLI описаны в [документации Telegram Serverless](https://core.telegram.org/bots/serverless). В версии CLI 0.2.0 фронтенд Mini App публикуется из каталога `static.source` файла `tgcloud.json`; в этом проекте это `dist/`.

1. В @BotFather убедиться, что для **@umnozhayka_tgbot** включён Serverless.
2. В **Serverless → CLI Access → Access token** получить отдельный CLI-токен формата `app<id>:<secret>`. Это не Bot API token. Не передавать токен в чат, Issues, PR, логи или репозиторий.
3. В корне клона выполнить проверки и собрать статику:
   ```bash
   npm ci
   npm run check
   ```
4. Связать локальный проект с ботом: выполнить `npx tgcloud login` и вставить CLI Access token только в локальный интерактивный prompt. CLI сохраняет его в `.tgcloud/`, игнорируемый Git. CLI показывает app ID, но не username бота. Владелец должен получить токен из Serverless-настроек именно **@umnozhayka_tgbot** в BotFather и сверить app ID из `status` с публичным префиксом токена; секретную часть никуда не копировать. Если переменная `TGCLOUD_TOKEN` не используется намеренно, сбросить возможное старое значение в текущей оболочке (`unset TGCLOUD_TOKEN`): заданная переменная переопределяет сохранённый CLI token.
5. Получить текущий снимок из облака и изучить расхождения:
   ```bash
   npx tgcloud fetch
   npx tgcloud status
   npx tgcloud diff
   ```
   `status` и `diff` сравнивают рабочую копию с сохранённым снимком; `status` дополнительно может показать состояние webhook. Они не обновляют снимок модулей и статики из облака, поэтому перед ними обязателен `fetch`. Владелец подтверждает целевого бота по BotFather-разделу, из которого был получен токен, и совпадению app ID; также проверить, что план не удаляет или не заменяет неизвестные модули. Если происхождение токена или изменения не ясны, остановиться и ничего не публиковать.
6. После проверки снимка выполнить `npm run deploy`. Скрипт заново собирает `dist/` и запускает `tgcloud push`. Не добавлять `--force`: при конфликте выполнить `fetch`, разобраться с изменениями и повторно проверить `status`/`diff`.
7. Сохранить фактический URL `https://app<app_id>.tgcloud.ai/`, напечатанный CLI. В @BotFather настроить **Menu Button** на этот URL.
8. Отправить боту `/start`, открыть Mini App кнопкой меню и проверить приложение на реальном телефоне: режимы, свайпы, завершение, таймер и восстановление позиции. Отдельная БД и миграции пока не нужны.

CLI-токен требуется для привязки локальной машины и просмотра актуального состояния. Если токена ещё нет, владелец получает его самостоятельно в BotFather по пути из шага 2 и вводит локально. Передавать его помощнику не нужно.

Не запускать `tgcloud push --force` при конфликте. Не добавлять токены в коммиты или CI.

## Текущий статус релиза — 2026-10-22

- PR [#5](https://github.com/dvpot/umnozhayka/pull/5) merged в `main` (`2b7f928a6c1586413494fc2c8edca2ff04c82e3e`). Из `tgcloud.json` удалён `X-Content-Type-Options`: CLI 0.2.0 запрещает переопределять этот транспортный заголовок. В опубликованном ответе платформа возвращает `X-Content-Type-Options: nosniff`; `Referrer-Policy: no-referrer` задаётся проектом.
- Serverless revision `1`: два модуля и четыре static-файла подтверждены через `tgcloud fetch`; `tgcloud status` показывает `Webhook: in sync` и `Static: Up to date`.
- URL Mini App: <https://app8854507045.tgcloud.ai/>. HTTP-проверка вернула `200`; Chromium smoke-test прошёл на ширинах 320, 390 и 768 px, включая 81 и 9 уникальных упражнений, завершение, свайп, localStorage и таймер.
- В этом релизе `tgcloud push` загрузил модули и статику, но CLI 0.2.0 завершился с ошибкой при записи локального snapshot. Последующий `tgcloud fetch` подтвердил revision `1` и все четыре файла. Если после push возникает такая ошибка, сначала выполнить `fetch` и `status`, чтобы проверить состояние сервера; не повторять публикацию вслепую.

### Осталось владельцу бота

Настроить Menu Button в @BotFather для `@umnozhayka_tgbot`: команда `/setmenubutton` → выбрать бота → указать текст (например, `Играть`) и URL <https://app8854507045.tgcloud.ai/>. Затем отправить боту `/start`, открыть Mini App кнопкой меню и проверить запуск на телефоне. До этой проверки запуск Mini App непосредственно из Telegram считается неподтверждённым, даже если static URL доступен.
