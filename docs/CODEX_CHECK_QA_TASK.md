# Codex на Ubuntu VM — приёмка тренировки и проверки

Рабочий каталог `/home/dvpot/projects/github/umnozhayka`. Источник истины — `dvpot/umnozhayka`, ветка `main`. Прочитай `AGENTS.md`, `README.md`, `docs/PLAN.md`, `docs/TELEGRAM_DEPLOY.md`, `docs/BOT_PROFILE.md` и Issue #3. Начни с `git status -sb` и `git fetch origin`. Синхронизируй чистый `main` через fast-forward, запиши точный SHA. При локальных изменениях сохрани их и используй отдельный checkout или worktree для проверки. Исправления оформляй отдельным PR с CI.

1. Выполни `npm ci && npm run check`. Раздай `dist/` локальным HTTP-сервером. В браузере проверь минимум 320 и 390 px, на 280 и 768 px проверь отсутствие горизонтальной прокрутки. Проверь на 320 px доступность всех кнопок, включая прокрутку на невысоком экране.
2. В «Тренировке» проверь подсказку по нажатию на `?` и через 10 секунд, три варианта ответа, повтор после ошибки, стрелки и свайпы. Выбери ×10, продвинься на второй пример и переключись в «Проверку». Первая проверка должна начать ×10 с первого примера.
3. В «Проверке» проверь ввод цифр, удаление последней, отсутствие системной клавиатуры при касании, недоступность проверки пустого ответа и перехода до оценки. Ответь сначала неверно, затем верно. Проверь оба счётчика, скрытие клавиатуры после оценки, переход стрелкой, свайпом и клавишей →, невозможность повторной оценки или возврата к ответу. Для 10×10 введи `100`. Дойди до итога 10 примеров и сверь его с ответами. Проверь, что «Все» содержит 100 примеров, а перемешивание не даёт дублей.
4. Перезагрузи страницу после оценки и на итоговом экране. Проверь восстановление режима, счёта и позиции. Проверь отмену сброса, затем подтверждение сброса и нулевой счёт. Вернись в «Тренировку» и проверь её сохранённую позицию.
5. На проверенном SHA выполни последовательно `npx tgcloud fetch`, `npx tgcloud status` и `npx tgcloud diff`. Сверь целевое приложение `8854507045` для `@umnozhayka_tgbot`, текущую ревизию и список файлов. Ожидаемый diff — статика Mini App. При неожиданных серверных изменениях выясни причину. Используй настроенный CLI, не запрашивай и не выводи секреты.
6. В этой задаче подготовь результат preflight. Публикация идёт по отдельному релизному шагу из `docs/TELEGRAM_DEPLOY.md`. Верни в чат точный SHA, команды и фактические результаты, браузер и размеры экрана, app ID, ревизию, список ожидаемых и неожиданных изменений, ссылку на PR при наличии исправлений. Отмечай отдельно то, что удалось проверить на реальном Telegram-клиенте.
